chy is a byte-sized, portable, source-based package manager written in POSIX shell. 1.6k lines of pretty shell with no dependencies.

Packages are recipe based and easily tweakable.

Everything lives under $CHY_ROOT, ~/.chy by default. chy builds each package into store/ and links it into a usr/ symlink farm. State is plain files. Nothing runs as a daemon and no step needs privilege. chy never writes outside its root, so deleting that directory removes everything it has built. Running chy with no arguments prints the verb list.

A farm with three packages:

$CHY_ROOT/
├── recipes -> ~/chy/chy-recipes/recipes
├── overlay/
├── store/
│   ├── zlib-1.3/
│   ├── libpng-1.6/
│   └── freetype-2.13/     each package is its own prefix
└── usr/
    └── bin/               symlinks back into store/

Getting Started

git clone https://github.com/alperien/chy && cd chy
git clone https://github.com/alperien/chy-recipes
export CHY_ROOT=$HOME/.chy PATH="$HOME/.chy/usr/bin:$PATH"
mkdir -p "$CHY_ROOT" && ln -s "$PWD/chy-recipes/recipes" "$CHY_ROOT/recipes"
cp chy-recipes/shlibs.map "$CHY_ROOT/shlibs.map"
sh chy/chy install freetype

Recipes

A recipe is a directory of plain files: version, sources, checksums, depends, makedepends, a build script, and patches/. To change a package, copy its recipe to $CHY_ROOT/overlay/<name> and edit it there; chy reads the overlay first. chytrans (translator/) generates every recipe from Void Linux's templates, so the recipe set tracks upstream. Fixes go into the translator, and pull requests that edit recipes/ get closed.

The whole recipe set, the Firefox runtime spine over an X11-provided host (30/07/2026):

zlib bzip2 xz zstd libffi expat pcre2 glib libpng freetype harfbuzz
fontconfig pixman cairo pango gdk-pixbuf libepoxy at-spi2-core gtk+3
dbus

firefox is a binary exception, seeded by hand, so it is not listed.
